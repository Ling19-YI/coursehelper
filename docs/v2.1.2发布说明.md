## 更新内容

### 修复：接口地址填成「完整接口路径」时，一直报接口 400

有用户反馈答题始终报错：

```
多模态 接口 400 … "No static resource api-openai/v1/chat/completions"
```

原因是**接口地址要把服务商文档里的完整路径整段填进去了**。软件调用时会在你填的地址
后面自动拼 `/chat/completions`，所以填成 `…/v1/chat/completions` 时，真实请求会变成
`…/v1/chat/completions/chat/completions`——服务端找不到这个路径，只回一句
「No static resource …」，日志里看就是「接口 400」，完全看不出是自己填错了。

这版开始**自动纠正**：保存时会去掉多余的 `/chat/completions` 结尾，顺带处理尾斜杠和
误粘的引号；**已经填错、存在本机配置里的地址，不用重新保存也会被自动纠正**，直接再跑
一次任务即可。设置页也补了一句说明——直接粘贴服务商的完整接口路径也可以。

正确填法示例（填到 `/v1`、`/v4` 这一层为止）：

| 服务商 | 接口地址 |
|---|---|
| DeepSeek | `https://api.deepseek.com/v1` |
| 智谱 | `https://open.bigmodel.cn/api/paas/v4` |
| 通义（阿里百炼） | `https://dashscope.aliyuncs.com/compatible-mode/v1` |

### 改进：接口报错会带上服务端返回的原文

除了 401（明确是密钥无效），其他失败现在会把服务端返回的报错原文（前 140 字）
一起写进日志。「地址填错」「模型名不存在」「额度用尽」这类问题一眼能分辨，
不用再靠猜。
