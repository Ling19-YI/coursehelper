# 刷课助手 v2.1.0 推广方案

> 定稿时间：2026-10-13
> 适用版本：v2.1.0（GitHub + GitCode 双源）

---

## 一、先看清楚现在站在哪

| 项目 | 实测值 |
|---|---|
| GitHub 安装包下载 | 1682 |
| GitCode 下载（用户统计） | ~1700 |
| 双平台合计 | **~3400** |
| 最新版本 | v2.1.0，发布于 10-12 |
| 推广素材 | 横版 30s、竖版 30s各一（**脚本还停留在 v1.5.1**） |
| 落地页 | 已做好，**未部署，无域名** |

三个结论：

1. **流量不缺，缺的是沉淀。** 3400 次下载却没有官网、没有订阅入口，等于每次发版都要重新攒一遍人。
2. **落地页已经写好了，部署是投产比最高的一步。** 一次部署，所有渠道共用，成本几乎为零。
3. **视频脚本滞后于产品两代。** 现在拿旧脚本发出去，观众点进去发现没有"AI 答题"，转化会打折。

## 二、第一优先级：把落地页部署掉

### 为什么是这件事排第一

现在流量路径是：视频/帖子 → GitHub 发行页 → 下载 → 结束。

问题在于发行页只能提供"下载"这一个动作，而落地页能提供：
- 讲清"账号只存本机"这类**决定用户敢不敢装**的信任信息
- 展示更新日志，让老用户知道有新版
- 引导 star / 反馈，**把一次性下载者变成可再触达的存量**
- 放收款码（GitHub 发行页放二维码会被折叠/屏蔽）

### 部署方案（按推荐顺序）

| 方案 | 域名 | 国内速度 | 成本 | 备注 |
|---|---|---|---|---|
| **Cloudflare Pages** | `*.pages.dev` | 一般 | 免费 | 推荐，国内可访问，无需备案 |
| **Vercel** | `*.vercel.app` | 一般，偶有波动 | 免费 | 备选 |
| **GitHub Pages** | `*.github.io` | 慢 | 免费 | 仓库私有则不可用 |
| **国内服务器** | 自有域名 | 快 | 需备案 | 只有日均 UV 上百后才值得 |

**落地步骤（Cloudflare Pages）：**

```bash
cd "C:/Users/colorful/Documents/Default Project/coursehelper"

# site/ 目录就是纯静态站，直接部署即可
npx wrangler pages deploy site --project-name coursehelper
```

部署后把 `site/index.html` 里的下载按钮换成短链（推荐 Cloudflare Worker 或 Redirect 服务），不要直接暴露带 `?noCache` 的长参数串——那串查询参数是给自动更新用的，人点会 404。

### 部署完立刻要做的三件事

- [ ] 在 README 顶部和两个发行页描述里挂上落地页地址
- [ ] 落地页加一个 **"订阅更新"** 输入框（存 GitHub Releases RSS 地址，收集邮箱或直接链 RSS）
- [ ] 把收款码在落地页、关于页、发行页描述三处对齐

## 三、第二优先级：视频脚本升级到 v2.1.0

现有脚本讲的是"应用内更新""视频自动播放"，这些还是 v1.5.1 的卖点。v2.1.0 的真实差异点更有传播力：

| 新卖点 | 为什么能传播 |
|---|---|
| 一章多任务点真正跑完 | 这是最硬的bug 修复，用户能感知 |
| 截图识题 / 看图答题 | AI 能力，第一次出现在功能列表里 |
| 遇到人脸识别会停下等你 | **反向卖点**——别人都在吹"全自动"，你讲"它会停下来"，反而建立信任 |

详见 `视频脚本-v2.1.0.md`，里面有横版/竖版分镜和现成的口播稿。

**发布节奏：** 脚本改好后用现成的 `promo/` 流水线重新出片，命令在同文件末尾。

## 四、第三优先级：分发矩阵

### 渠道分工（不要平均用力）

| 渠道 | 定位 | 内容形态 | 频次 | 优先级 |
|---|---|---|---|---|
| B 站 | 拉新主力，搜索沉淀好 | 60–90s 横版教程 | 每月 1–2 | P0 |
| 抖音 / 视频号 | 泛流量，跑量测试钩子 | 20–30s 竖版 | 每周 1–2 | P0 |
| 小红书 | 女生用户集中，长尾搜索强 | 图文 6–9 张 | 每周 1 | P1 |
| 贴吧 / 知乎 | 长尾，接住搜索流量 | 图文 / 长文 | 每周 2 | P1 |
| GitHub / GitCode issue | 老用户口碑 + 反馈收集 | 更新说明 + 回复 | 持续 | P0 |
| 校园社群 | 精准，但易被判定广告 | 私域 | 谨慎 | P2 |

### 一个必须遵守的红线

**视频平台和内容平台对"自动化"的审核比 Git 严格得多。** 历史教训：宣传口径一旦被判定为"绕过平台限制"，轻则限流，重则删稿封号。

具体做法：

- 标题、简介、字幕、口播里**不出现**这些词：`绕过`、`破解`、`代刷`、`秒过`、`挂科`、`作弊`、`免签`
- 统一用中性表达：桌面助手、自动播放、任务点、断点续跑、仅供学习研究
- **不要在简介里贴裸链接**，放"详情看主页/置顶评论"，这是被判导流最常见的原因
- 站内推广页保留免责声明（README 和落地页都已有，不要删）

具体各平台文案已经写好，见 `各平台文案-v2.1.0.md`。

## 五、第四优先级：把3400 个下载者变成存量

这是长期收益最高、但最容易被忽略的一环。

### 1. 开Issue 区引导反馈

两个仓库的 issue 都开着，但需要一个明确的引导入口。在 README 和落地页加一句：

> 用得有问题请开issue，我会逐条看。附上日志页截图能快很多（记得遮住账号和路径）。

### 2. 建一个更新公告出口

推荐**双保险**，成本几乎为零：

- GitHub Releases RSS：`https://github.com/Ling19-YI/coursehelper/releases.atom`
- 落地页放 RSS 订阅按钮

有条件再补一个微信群 / QQ 群，但**一定要克制**：拉群之后必须有更新，否则一个月内就散了，比不建更伤。

### 3. 把 star 数当北极星指标

star 是所有渠道里唯一能被别人看到的"社会证明"。落地页应该有一句"GitHub 已有 N stars"，N 从 API 取。小工具用 `https://api.github.com/repos/Ling19-YI/coursehelper`。

## 七、别做的事

| 别做 | 原因 |
|---|---|
| 在多个平台复制粘贴同一段文案 | 平台判定重复/营销内容，直接降权 |
| 承诺"支持雨课堂" | 还在 `feat/multi-platform` 分支，**没合并** |
| 宣传里放"内测/破解版"字样 | 审核风险极高 |
| 依赖单一平台流量 | 一个号被封就断流，至少要双平台并行 |
| 把收款码作为宣传主诉求 | 容易触发风控，"自愿、不影响使用"这句要保留 |

## 八、一句话总结

**先花一小时把落地页部署掉，再花一天重出视频，剩下的都是日常运营。**
现在最大的问题不是没人知道，而是知道的人没有沉淀下来。
